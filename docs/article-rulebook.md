# Qiita記事ルールブック

このルールブックは、本プロジェクトで生成する記事の品質・一貫性を保つための基準です。
Claude へのプロンプトにも参照指示として含まれます。

---

## 1. 文体・トーン

| 項目 | ルール |
|------|--------|
| 文体 | 敬体（です・ます調）に統一する |
| 人称 | 「私」は使わない。主語が必要なら「筆者」 |
| 読者への呼びかけ | 「あなた」は避け、「読者の方」「皆さん」を使う |
| 断定表現 | 根拠のない断定は避ける（「〜と思います」より「〜です」を優先しつつ、不確かな情報には「〜の場合があります」） |

---

## 2. 構成

### 必須セクション

1. **はじめに** — この記事で何を学べるかを明示する
2. **環境・前提条件** — OS、Node.js バージョン、必要な知識を明示する
3. **本文（手順）** — 番号付きリストまたは見出しで整理する
4. **まとめ** — 学んだことを箇条書きで振り返る

### 任意セクション

- 参考リンク
- 関連記事
- 次のステップ

---

## 3. 見出し

- `#`（h1）はタイトルのみ。本文では使用禁止
- `##`（h2）で大セクションを区切る
- `###`（h3）を小セクションに使う
- `####` 以下は原則使用しない

---

## 4. コードブロック

- 必ず言語識別子を付ける

  ````
  ```typescript
  const message = "Hello";
  ```
  ````

- ファイル名を示す場合はコードブロック直前にコメントで記載する

  ````
  ```typescript:src/index.ts
  const message = "Hello";
  ```
  ````

- 実行コマンドは `bash` または `shell` を使う
- 出力例は `text` または `plaintext` を使う

---

## 5. Qiitaフロントマター

生成する記事には必ず以下のフロントマターを付ける。

```yaml
---
title: 記事タイトル
tags:
  - タグ1
  - タグ2
private: false
updated_at: ''
id: null
organization_url_name: null
slide: false
ignorePublish: false
---
```

- `tags` は最大5つ
- `private: false` をデフォルトとする（レビュー前に変更可）
- `id: null` は投稿前の状態を示す

---

## 6. 禁止事項

- 著作権が不明な外部コードをそのまま引用しない
- 公式ドキュメントなしに「〜するべき」という強い断定をしない
- 特定企業・サービスを根拠なく批判・比較しない
- 内容のない文字埋め（「以上のようにして〜することができました」など）は削除する

---

## 7. 文字数・分量の目安

| 対象読者 | 目安文字数 |
|----------|-----------|
| beginner | 2,000〜3,500字 |
| intermediate | 1,500〜3,000字 |
| advanced | 1,000〜2,500字 |

- コードブロック内の文字はカウント対象外
- 長すぎる記事は「前編・後編」に分割することを推奨

---

## 8. レビューチェックリスト

生成後に `npm run review` で確認する項目。

- [ ] フロントマターが正しい形式か
- [ ] 見出し構成が適切か（h1 の重複なし）
- [ ] コードブロックに言語識別子があるか
- [ ] 文体が敬体に統一されているか
- [ ] 環境・前提条件セクションがあるか
- [ ] まとめセクションがあるか
- [ ] 文字数が目安の範囲内か
